### MapLibre development-worker fix

The first manual run showed the map controls and background but no country
geometry. Vite reported that `maplibre-gl-worker.mjs` was missing from its
optimized dependency directory. MapLibre 6 keeps its renderer in a sibling ESM
worker; Vite's pre-bundling moved the main module without preserving that runtime
relationship. `vite.config.ts` now excludes `maplibre-gl` from `optimizeDeps`, so
development serves the package's native ESM files together. A running Vite
process must be restarted once after this configuration change.

The result view exposed a second, independent map issue during the complete
five-round browser test. Passing `[guess, answer]` directly to `fitBounds` is
unsafe because the points are not guaranteed to be ordered south-west then
north-east. MapLibre could therefore interpret the bounds as wrapping around
the world and move both markers off-screen. The implementation now creates an
empty `LngLatBounds` and extends it with both points; this normalizes the corners
before fitting the viewport.

## Dependencies added

```powershell
corepack pnpm --filter @golukituki/core add zod
corepack pnpm --filter @golukituki/web add maplibre-gl
corepack pnpm --filter @golukituki/web add -D @testing-library/react @testing-library/user-event
```

`zod` defines one executable schema used at the API boundary rather than keeping
separate handwritten validation and TypeScript types. MapLibre will render the
self-hosted Natural Earth GeoJSON without a provider key or runtime tile quota.
The package exposes identity constants through a separate `./identity` entry so
the current browser bundle does not include Zod merely to display the app name.
Testing Library drives the React UI through the same labels and buttons a user
sees. The MapLibre component is mocked only in the component test, keeping that
test deterministic while the real map is covered by browser QA.

No Python dependency was added. The fixture acquisition step uses `urllib`,
`json`, `hashlib`, and coordinate math from the standard library, so installing
`uv` at this point would not improve reproducibility.

## Satellite fixture acquisition

The reproducible command is:

```powershell
python -m scripts.geodata.src.golukituki_geodata.fetch_m1_fixtures
```

For every city in `data/cities.json`, the script:

1. sends a point intersection query to the Microsoft Planetary Computer STAC
   API for Sentinel-2 L2A scenes from 2024–2025 with less than 15% cloud cover;
2. chooses the result with the lowest scene-level cloud-cover value;
3. requests a 512×512 natural-color Web Mercator tile at zoom 12;
4. derives an opaque filename from the source item and tile coordinate;
5. calculates the exact center of that displayed tile as the answer;
6. writes item ID, acquisition time, cloud cover, coordinates, and attribution
   to the private-repository source manifest.

The first bounding-box query produced a black Daegu tile because a Sentinel
scene intersected the search rectangle without covering the city point. The
query was corrected to a GeoJSON `Point`, all five files were regenerated, and
each output was checked visually. This failure is recorded because data-pipeline
validation is part of the implementation, not an optional cleanup step.

Files:

- `data/source/m1-satellite-fixtures.json` — provenance and server answers;
- `apps/web/public/clues/*.png` — five opaque runtime images;
- `apps/web/public/map/south-korea.geojson` — extracted Natural Earth geometry.

The displayed credit is `Contains modified Copernicus Sentinel data (year)`.
The data API workflow follows the [official Planetary Computer
guide](https://planetarycomputer.microsoft.com/docs/quickstarts/using-the-data-api/).

## Domain rules

The shared `@golukituki/core` package owns pure rules used by the Worker and
eventually the browser:

```text
distance = haversine(guess, tile center)
points   = round(5000 × exp(-distanceKm / 50))
```

Each round is limited to 0–5000 points. A nickname is trimmed, normalized to
Unicode NFC, and may contain Unicode letters, numbers, spaces, `_`, and `-`.
Repeated whitespace and unsupported punctuation are rejected.

## D1 model

Migration `0002_m1_satellite_game.sql` adds:

- `round_assets`: clue path, private answer, attribution, source reference;
- `games`: nickname, mode, state, current round, total, 24-hour expiry;
- `game_rounds`: shuffled asset assignment and accepted guess result.

The browser never queries D1. Only the Worker binding can read answer columns.
The five development assets are seeded by the migration. The migration was
successfully applied to the local Wrangler database with:

```powershell
corepack pnpm db:migrate:local
```

## API contract

### `POST /api/games`

Input:

```json
{ "nickname": "민수", "mode": "satellite" }
```

The Worker selects five enabled assets in random order, creates the game and
round rows, and returns the first opaque clue. No answer coordinate is present.

### `GET /api/games/:gameId`

Restores a game after refresh. Completed rounds include their revealed results;
the active round contains only its clue URL, attribution, number, and opaque ID.

### `POST /api/games/:gameId/guesses`

Input:

```json
{ "latitude": 37.5, "longitude": 127.0 }
```

The Worker loads the current private answer, calculates distance and points, and
uses `UPDATE ... WHERE guessed_at IS NULL`. Only the request that changes one
row can continue. It then advances the game and returns the completed result
plus the next clue, or a completed-game snapshot after round five.

All API responses use `Cache-Control: no-store` and structured error codes.
Request bodies larger than 2 KiB are rejected.

## How the browser flow works

`App.tsx` owns the small client-side state machine. Starting a game sends the
nickname and mode to the Worker, saves only the opaque game ID in `localStorage`,
and renders the clue returned by the API. A map click stores a tentative
latitude/longitude in React state; no request is made until the player confirms
the guess. The Worker response replaces the local snapshot and is the sole
source of distance, points, answer coordinates, and total score.

After a successful guess, `GuessMap.tsx` draws two markers and a dashed GeoJSON
line, then fits the viewport around them. Moving to the next round clears those
overlays and returns the map to the country overview. Reloading the page reads
the opaque game ID and calls `GET /api/games/:gameId`; it does not reconstruct
game state in the browser.

MapLibre is loaded with `React.lazy`. This keeps roughly 1.03 MB of minified map
code out of the initial application chunk. The production build measured about
281 kB for the initial JavaScript and 1.03 MB for the separately loaded map
chunk (about 89 kB and 281 kB gzip respectively). The large lazy chunk warning
is expected for MapLibre; hiding the warning would not improve what users
download.

`apiRequest` also handles an empty or non-JSON server response explicitly. This
turns a low-level JSON parsing exception into a useful status-based application
error, which matters when a local Worker is not running or a proxy fails.
