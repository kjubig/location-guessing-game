## Installation procedure

The repository pins pnpm in the root `package.json`. Installation uses:

```powershell
corepack prepare pnpm@10.17.1 --activate
corepack pnpm install
```

Why Corepack: it downloads the package manager version declared by the project,
instead of relying on an arbitrary globally installed pnpm. The generated
`pnpm-lock.yaml` records exact transitive versions for CI and future checkouts.

The Python project is scaffolded in M0 but has no external runtime dependencies.
`uv` will be installed only when a geospatial dependency is first required; that
installation is intentionally not hidden inside another command.

### Installation issue: Wrangler peer types

The first install correctly failed because strict peer checking found that the
resolved Wrangler version requires `@cloudflare/workers-types` 5.x while the
initial manifest requested 4.x. The fix was to update the declared types package
to the compatible 5.x line and keep `strict-peer-dependencies=true`. Disabling
the check would make installation green while leaving potentially incompatible
runtime declarations in the editor and type checker.

### Validation issue: workspace exports before build

The first lint run could not resolve shared types because `@golukituki/core`
exported only its future `dist` output, while lint intentionally runs before the
build. Workspace consumers now resolve the TypeScript source directly; Vite and
Wrangler compile it as part of their own bundles. The package still has a
separate declaration build, so publishable output is verified without making
local type analysis depend on an earlier command.

### Validation issue: build plugins in unit tests

Vitest initially loaded the full Vite configuration, including the Tailwind build
plugin, even though the frontend unit test only needs TypeScript and i18n. A
dedicated `vitest.config.ts` now gives unit tests a small Node environment and an
explicit test-file pattern. Production Vite plugins are still exercised by the
separate build step.

## How the M0 request works

1. React renders the foundation page.
2. `App.tsx` requests `/api/health`.
3. In development Vite proxies that path to Wrangler.
4. Hono matches `GET /api/health` and returns typed JSON.
5. Middleware attaches `Cache-Control: no-store` and `X-Content-Type-Options`.
6. React changes the visible API status to online and shows the environment.

## Environment isolation

`wrangler.jsonc` declares top-level local configuration plus explicit
`production` and `preview` environments. D1 bindings are non-inheritable
Cloudflare configuration, so each environment repeats its own binding and
database ID. Deploy commands always include the target environment, preventing
an ambiguous Wrangler deploy. The committed zero UUIDs are safe placeholders and
make the required replacement obvious before remote deployment.
