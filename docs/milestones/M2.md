# M2 technical journal — metro mode

Status: playable vertical slice complete; detailed vector basemap pending
Date started: 2026-09-18

## Scope boundary

M2 adds real OpenStreetMap metro geometry, anonymized clue files, a metro game
mode, and a more detailed guessing map. Rankings, Turnstile, rate limiting, and
the final production content pass remain outside this milestone.

## Data-flow decision

The acquisition and transformation steps are deliberately separate:

1. a Python command sends bounded, sequential Overpass queries and caches each
   raw response under ignored `data/raw/m2-metro/`; it waits between cities and
   can fall back to a second public instance after an HTTP/routing failure;
2. the deterministic transformer selects a real station near each configured
   city reference point;
3. nearby subway/light-rail ways are projected into local kilometre offsets;
4. those offsets are scaled into a 1000×760 drawing canvas;
5. the browser receives only anonymous integer points, while the manifest and
   D1 seed retain the real answer coordinate.

CI tests only the deterministic transformation with a tiny in-memory OSM
fixture. It never calls a public Overpass server.

## Why the raw cache is ignored

Overpass responses can be large and can change when OpenStreetMap is edited.
Keeping the download locally avoids repeatedly loading a community service.
The committed private manifest records the exact query and SHA-256 checksum, so
a reviewer can still identify the input used for every generated clue. Passing
`refresh=True` is an explicit future refresh operation rather than the default.

## Public clue contract

Each `/clues/metro/<opaque-id>.json` file contains only:

- `schemaVersion`;
- an abstract canvas width and height;
- line paths as arrays of integer `[x, y]` points;
- station dots as integer `[x, y]` points.

It contains no OSM IDs, tags, names, city identifier, longitude, or latitude.
The pipeline rejects forbidden keys/strings and coordinates outside the drawing
canvas before writing an asset.

## Commands

Run deterministic pipeline tests:

```powershell
corepack pnpm pipeline:test
```

Acquire cached data and generate all configured development clues:

```powershell
python -m scripts.geodata.src.golukituki_geodata.build_m2_metro
```

The acquisition command needs internet access once. Re-running it uses the
local cache and performs no network request.

## First real acquisition

The primary Overpass instance initially returned HTTP 429. The first fallback
served Seoul, Busan, Incheon, and Daegu, then timed out on Daejeon. A third
fallback completed only that missing request; the four successful cache files
were not downloaded again. The resulting source cache is about 3.7 MB and stays
ignored. Five committed clues range from roughly 2–22 kB.

The renderer intentionally uses one neutral line color, north-up geometry,
rounded joins, and hollow station dots. Nearby duplicate stop/platform points
are merged in drawing space so dense OSM tagging does not turn into unreadable
clusters.

## Application integration

- `GameMode` accepts `satellite` and `metro`;
- the Worker chooses assets by mode and applies an 8 km metro scoring scale;
- migration `0003_m2_metro_mode.sql` widens the D1 constraints without deleting
  existing games, then seeds five real metro answers;
- the start screen offers an accessible two-option mode picker;
- `MetroClue.tsx` validates fetched JSON before drawing it as SVG;
- completed round responses carry their own attribution, preventing the result
  screen from accidentally showing the next round's credit.

The first migration attempt proved that replacing only the two parent tables
breaks existing `game_rounds` foreign keys. D1 rolled that attempt back. The
final migration copies all three related tables, drops the old set child-first,
renames the new set, and then recreates indexes. It executed 19 commands
successfully against the existing local database.

## Verification so far

- five real metro clue files pass the automated coordinate/name leak check;
- a full five-round metro game completed through Vite, Wrangler, and local D1;
- all five generated diagrams were inspected and remained legible from the
  sparse Daejeon network to the dense Seoul network;
- result markers, the 8 km scoring curve, attribution, and the final summary
  worked with no browser console warnings or errors;
- unit/component tests cover metro schema acceptance, score configuration,
  mode selection, JSON validation, and SVG output.

## Remaining M2 work

The guessing map still uses the M1 Natural Earth country outline. Completing M2
requires a filtered OSM-derived vector tile set through zoom 12 containing
water, selected roads, and boundaries but no rail/transit features. That step
needs Python GIS/vector-tile packages managed by `uv`; `uv` is not currently
installed on this workstation. Installation and every added package will be
recorded here before the tile generator is implemented.
